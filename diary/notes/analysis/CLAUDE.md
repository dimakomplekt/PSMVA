# CLAUDE.md

Этот файл — руководство для Claude Code (claude.ai/code) при работе с кодом в этом репозитории.

## Проект

PSMVA — десктопное приложение на C++17 (Windows/MSVC, только x64) на базе SDL3 + OpenCV для анализа высокоскоростной видеосъёмки плазменного напыления: пользователь настраивает OpenCV-маски GUI-фейдерами, программа обрабатывает кадры и формирует отчёт по характеристикам потока. Весь интерфейс рисуется вручную средствами SDL3 (собственная библиотека виджетов, без внешних GUI-фреймворков). Тексты интерфейса двуязычные (EN/RU); дневник разработки и заметки по дизайну — в `diary/` (на русском).

Полное описание архитектуры — в `ARCHITECTURE.md`.

## Сборка и запуск

Тестов и линтера нет; единственный рабочий процесс — собрать и запустить:

```powershell
./run.ps1   # конфигурация CMake в build/, сборка Release, запуск exe
```

Вручную то же самое:

```powershell
cmake -S . -B build
cmake --build build --config Release
.\build\Release\PSMVA.exe
```

- Требуется OpenCV, собранный в `C:/opencv/build` (путь жёстко задан в CMakeLists.txt), с runtime-DLL в `C:\opencv\build\x64\vc16\bin` (run.ps1 добавляет этот путь в PATH).
- SDL3 / SDL3_ttf / SDL3_image вендорены в `libs/engine/`; их DLL копируются к exe post-build.
- Исходники собираются рекурсивным глобом (`src/*.cpp`, `libs/**/*.cpp`) с `CONFIGURE_DEPENDS` — новый .cpp подхватывается автоматически, править CMakeLists.txt не нужно.
- `libs/program_gui/basic_elements/content/` (шрифты) копируется post-build в `<папка exe>/content/`; ресурсы в коде загружаются только через `absolute_by_relative_from_exe("content/...")`, никогда — путями относительно текущего каталога.

## Ключевые механики, которые нужно соблюдать

- **Приложение — иерархическая машина состояний.** Экраны — это состояния со `State_ID` ({0} START → {1} MAIN_MENU → {1,1} FILE_CHOOSE → {1,2} MASKS_SETUP → {1,3} FLOW_PARAMETERS_CALCULATION → {1,4} REPORT_FORMING → {2} PROGRAM_END). Каждое состояние живёт в своей папке в `libs/program_logic/program_states/states_logic/` и предоставляет колбэки `<имя>_enter/_exit/_update/_render`, регистрируемые в `program_states.cpp::init_program_states()`. Состояния 1.3/1.4 существуют как файлы, но пока не зарегистрированы (закомментированы).
- **Никогда не переключать состояния изнутри колбэков** (клики кнопок, update, render). Вместо этого — `this_app.app_sm.request_state_change(TARGET_ID)`; переход выполняется в безопасной точке в начале `SDL_app_cycle()`, и этот кадр пропускается.
- **Главный цикл с частотными зонами.** Периодическая работа оборачивается в `if (App_timer_1.can_execute(Execute_zone_ID::HZ_240)) { ... }` (зоны: HZ_10000 / HZ_1000 / HZ_240 / HZ_120); разрешения сбрасываются каждый такт.
- **Глобальные сервисы — синглтоны, доступные через inline-ссылки**: `App_lang`, `App_palette`, `App_fonts`, `App_timer_1`, мышь/клавиатура через `GI_*` в `libs/engine/global_inputs/`. Смена языка и палитры доходит до виджетов через reset-флаги, опрашиваемые в главном цикле, — следовать этому паттерну, а не проталкивать обновления напрямую.
- **Строки интерфейса** — это записи `Lang_string_type` (пара EN + RU) в `libs/program_logic/global_data/program_dictionary/program_dictionary.h`, а не захардкоженные литералы.
- `libs/engine/engine.h` — зонтичный заголовок для includes уровня движка.

## Стиль кода (правила автора из diary/notes/copilot_rules.md — соблюдать)

- Везде snake_case; полные говорящие имена без сокращений (`panel_x_size`, а не `p_x_sz`). Константы и макросы — КАПСЛОКОМ. Имена классов/структур с заглавной буквы (`My_SDL_fader`, `State_machine`); методы и атрибуты — с маленькой.
- Однотипные вещи именуются однотипно, с одинаковым порядком слов: `shadow_width_size` / `background_width_size` (не `background_width`).
- Каждый файл начинается с коммента `// имя_файла.расширение` и делится на зоны разделителями `// ====…==== ИМЯ ЗОНЫ` (длинная форма `===========` для зон уровня файла, `// ===== имя =====` внутри классов/функций, `// Имя` для локальных групп). Порядок определений в .cpp повторяет порядок объявлений в .h, включая разделители зон.
- Функции с параметрами или возвратом комментируются в заголовке Doxygen-блоком `/** @brief ... @param ... @return */`, **без пустой строки между комментом и объявлением** (чтобы работал hover в IDE) и с одной пустой строкой коммента перед закрывающим `*/`. Void-функции без параметров — обычным `//`-комментом.
- Скобки в стиле Allman (открывающая на своей строке) — никогда K&R. Тривиальные `if` можно ванлайнером; длинные условия разбиваются по строкам, каждое подусловие в скобках. Длинные списки параметров — по одному на строку с группировкой пустыми строками.
- Комментарии на английском для всего переиспользуемого (engine, GUI-библиотека); временные пометки можно на русском.
- В конце файла — одна пустая строка.
