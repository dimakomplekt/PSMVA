# Отчёт об утечках памяти: причины, методика устранения, гайдлайн

Ответ на задачу из `diary/notes/analysis/leaks.md`. Исправленные версии файлов лежат рядом, в `fixed_files/` (в проект не внедрены).

---

## TL;DR

Подозрение из `leaks.md` подтвердилось: течёт связка `My_SDL_button` + вложенный `My_SDL_textbox`, и течёт именно **шрифтами (`TTF_Font`)**, а не текстурами. Корневая причина одна: **у указателя `ttf_font_link` нет однозначного владельца** — он то указывает на общий шрифт палитры (владелец — `App_fonts`), то на шрифт, открытый самим текстбоксом/кнопкой через `TTF_OpenFont`. Из-за этого закрывать шрифт «на всякий случай» было нельзя (можно убить общий шрифт палитры — отсюда закомментированные куски «destroys the logic»), и в итоге приватные шрифты не закрывает никто.

Численно: **каждый клик по любой кнопке навсегда теряет ~4 объекта `TTF_Font`**, каждое переключение шрифтовой палитры — **по 1 шрифту на каждую живую кнопку**. Один открытый `TTF_Font` — это загруженный файл шрифта + структуры FreeType + растущий кэш глифов (сотни КБ и больше). Это полностью объясняет наблюдение «поигрался с приложением — память выросла и не вернулась».

Наблюдение «обычный `My_SDL_textbox` не течёт» тоже подтверждается кодом: одиночные текстбоксы всегда сидят на общих шрифтах палитры и ничего не открывают сами.

## 1. Причины утечек (по местам в коде)

Номера строк — по текущим версиям файлов в `libs/program_gui/basic_elements/UI_elements/`.

### 1.1. Корневая причина: неопределённое владение `ttf_font_link`

`My_SDL_textbox::ttf_font_link` может указывать на:

* **общий** шрифт палитры (`App_fonts.get_current_fonts_palette()....ttf_font_link`) — им владеет `Global_fonts`, закрывать его текстбоксу нельзя;
* **приватный** шрифт, открытый самим текстбоксом или кнопкой (`TTF_OpenFont`) — его обязан закрыть тот, кто открыл.

Единственный признак — флаг `passed_by_font_palette`, но он переключается минимум в шести местах по разной логике и к моменту освобождения уже не отражает реальное происхождение шрифта. Поэтому старый код в `set_font_size()` (my_sdl_textbox.cpp:534–539) с прямым `TTF_CloseFont` действительно «ломал логику» — он иногда закрывал общий шрифт палитры. Его закомментировали — и все приватные шрифты стали бессмертными.

### 1.2. `My_SDL_textbox::set_font_size()` — открытие без закрытия (my_sdl_textbox.cpp:524–562)

```cpp
this->ttf_font_link = TTF_OpenFont(this->font_path.c_str(), this->font_size);
```

Каждый вызов открывает новый шрифт и молча затирает ссылку на предыдущий. Если предыдущий был приватным — он утёк. Это «протекающий кран», через который идут почти все остальные пункты.

### 1.3. Пресс-анимация кнопки — двойное открытие на каждом шаге (my_sdl_button.cpp:1183–1273)

На каждом шаге уменьшения шрифта при нажатии:

1. кнопка сама открывает шрифт: `TTF_Font* new_font = TTF_OpenFont(...)` (строка 1217);
2. `set_ttf_font_link(new_font)` — ссылка на `new_font`;
3. `set_font_size(new_size)` — **открывает ещё один шрифт того же размера** и затирает ссылку на `new_font`.

`new_font` осиротел — утечка. Шагов со сменой размера за одно нажатие обычно три (размеры base−1, base−2, base−2.5 округляются в 3 уникальных значения) → **~3 шрифта за клик**.

### 1.4. Release-путь пресс-анимации — осиротевший базовый шрифт (my_sdl_button.cpp:1243–1271)

При отпускании: `set_ttf_font_link(po_base_font)` возвращает базовый шрифт, но следом `set_font_size(po_base_size)` **опять открывает новый приватный шрифт** и затирает ссылку. Прежний приватный базовый шрифт (появившийся при `switch_button_textbox_type` на setup-е, см. 1.6) больше нигде не упоминается → **+1 шрифт за клик**. Заодно кнопка после отпускания сидит не на палитровом шрифте, а на свежем приватном дубликате.

Итого пункты 1.3 + 1.4: **~4 утёкших `TTF_Font` за каждый клик по каждой кнопке**. Именно поэтому «любое изменение графики» казалось текущим: и смена темы, и смена языка, и смена шрифта в меню делаются кликами по кнопкам — тёк сам клик.

### 1.5. Смена шрифтовой палитры — утечка на каждую кнопку (my_sdl_button.cpp:1027–1133)

В `reset_button_textbox_if_font_palette_switched()` для каждой кнопки: `set_ttf_font_link(новый палитровый)` затирает ссылку на приватный шрифт от предыдущего `set_font_size` (осиротел — утечка), затем `set_font_size(размер)` открывает новый приватный дубликат. → **1 шрифт на кнопку за каждое переключение шрифтовой палитры** (в главном меню 8 кнопок = 8 шрифтов за переключение).

### 1.6. `switch_button_textbox_type()` — бессмысленный приватный дубликат (my_sdl_button.cpp:353–451)

После установки палитровой ссылки `set_font_size(палитровый размер)` открывает приватную копию шрифта, который уже открыт палитрой в том же размере. Прямой утечки на setup-е нет (дубликат закрывается при выходе из стейта, палитровый общий — не наш), но именно этот дубликат становится «жертвой» пунктов 1.4 и 1.5, плюс это лишняя память и лишний дисковый I/O на каждую кнопку.

### 1.7. `My_SDL_textbox::cleanup()` — неверные условия освобождения (my_sdl_textbox.cpp:151–169)

```cpp
if (this->passed_by_font_palette && this->content_texture) SDL_DestroyTexture(...);  // текстура
if (!this->passed_by_font_palette) TTF_CloseFont(this->ttf_font_link);               // шрифт
```

* Текстура (`content_texture`) **всегда** принадлежит текстбоксу — но удаляется только при `passed_by_font_palette == true`. Для текстбокса с кастомным шрифтом (`set_font_path` / `set_font_size`) текстура течёт при каждом уничтожении. Кнопочные текстуры сейчас спасает только `My_SDL_button::cleanup()` с дублирующей логикой.
* `TTF_CloseFont(ttf_font_link)` при `!passed_by_font_palette` опасен: флаг мог сброситься (например, `switch_textbox_type(NO_TYPE)`), когда ссылка всё ещё смотрит на **общий** шрифт палитры — его закрытие оставит всем остальным текстбоксам висячий указатель (use-after-free / краш, а не утечка).

### 1.8. Мелочи рядом (исправлены заодно)

* `update_font()` (my_sdl_textbox.cpp:213): `TTF_Font* curr_font_link;` без инициализации — в ветке `default` читается мусор (UB). Исправлено на `= nullptr`.
* `My_SDL_button::cleanup()` (my_sdl_button.cpp:180–197): дублирует логику текстбокса с тем же неверным флагом; `TTF_CloseFont` без проверки на `nullptr` (в SDL_ttf 3 безопасно, но по факту — мёртвая ветка).

### 1.9. Что НЕ течёт (для полноты)

* Обычные `My_SDL_textbox` на палитровых шрифтах: текстура пересоздаётся с корректным `SDL_DestroyTexture` в `update_content_texture()`, шрифт общий. Совпадает с наблюдением.
* `My_SDL_texture`: уже сделан правильно — флаг `owns_texture` явно выражает владение. Этот же паттерн взят за основу исправления.
* Панели/фейдеры: SDL-ресурсов не держат.
* 21 шрифт палитр (3 палитры × 7 шрифтов) открывается один раз на старте и живёт до конца процесса — это **константная** память, не утечка.

## 2. Ответ на вопрос про глобальные указатели и «30 МБ не возвращаются к 4 МБ»

**Нет**, глобальное определение указателя (даже `My_SDL_panel* p = nullptr;`) не резервирует память под объект. Глобальный указатель — это 8 байт в статической секции. Память под объект выделяется только в момент `new` и возвращается аллокатору в момент `delete`. Никакого «максимально возможного объёма навсегда» не существует.

Почему же цифра в диспетчере задач не падает обратно:

1. **Реальные утечки** из раздела 1 — они честно копятся и не возвращаются.
2. **Аллокатор не отдаёт страницы ОС.** `delete` возвращает память в кучу CRT/Windows (Low Fragmentation Heap), а куча держит страницы «про запас» для следующих аллокаций. Private Bytes / Working Set в диспетчере при этом не уменьшаются, хотя память не потеряна — она будет переиспользована при следующем входе в стейт. Это нормальное поведение любого C++-приложения под Windows.
3. **Кэши вне вашей кучи**: SDL, FreeType (кэш глифов внутри каждого `TTF_Font`), видеодрайвер (текстуры) — тоже не сжимаются обратно.

Поэтому «память не вернулась после выхода из стейта» — сам по себе не признак утечки. Признак утечки — **монотонный рост при повторении одного и того же цикла**: 20 раз войти-выйти из MAIN_MENU, 50 раз кликнуть кнопку. Если после каждого круга цифра стабильно выше предыдущей — течёт; если после первого круга вышла на плато — это кэш кучи.

Чем мерить вместо диспетчера задач:

* **Visual Studio Diagnostic Tools → Memory Usage**: два снапшота кучи (до/после цикла) и диff по типам аллокаций.
* **CRT debug heap**: `_CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF)` в начале `main` — отчёт о неосвобождённых блоках при выходе (ловит только вашу кучу, `TTF_Font` там будет виден как блоки FreeType).
* **Счётчики ресурсов руками** — самый дешёвый способ именно для этого проекта: обёртки над `TTF_OpenFont`/`TTF_CloseFont` и `SDL_CreateTexture*`/`SDL_DestroyTexture` с глобальным счётчиком и логом. Разница счётчиков за цикл = точное число утёкших объектов.

## 3. Методика устранения (не ломающая архитектуру)

Идея взята из уже существующего в проекте правильного образца — `My_SDL_texture::owns_texture`. Владение выражается **не флагом «кто задал значение», а отдельным полем-меткой владения**.

### 3.1. Инвариант `owned_font`

В `My_SDL_textbox` добавлено поле:

```cpp
TTF_Font* owned_font = nullptr;   // шрифт, ОТКРЫТЫЙ самим текстбоксом; nullptr - когда
                                  // ttf_font_link смотрит на ОБЩИЙ шрифт палитры
```

Инвариант: `owned_font == nullptr` (сидим на общем шрифте) **или** `owned_font == ttf_font_link` (сидим на своём). Третьего состояния не бывает.

### 3.2. Две единственные точки смены шрифта

```cpp
void set_shared_font(TTF_Font* shared_font);   // взять ОБЩИЙ шрифт (палитры): закрыть свой
                                               // прежний, владение не брать
void set_owned_font(TTF_Font* new_owned_font); // взять СВОЙ шрифт (после TTF_OpenFont):
                                               // закрыть свой прежний, владение взять
```

Оба закрывают предыдущий `owned_font` (и только его — общие шрифты не трогаются никогда). Любое изменение `ttf_font_link` в коде класса и кнопки идёт только через эти два метода. Прямое присваивание `ttf_font_link = ...` запрещено.

### 3.3. Правила, которые из этого следуют (гайдлайн для всего нового кода)

1. **У каждого ресурса ровно один владелец.** Общие шрифты — у `App_fonts`. Текстура `content_texture` — всегда у текстбокса. Приватный шрифт — у текстбокса через `owned_font`. Элементы GUI — у стейта (`new` в enter, `delete_element()` в exit) или у панели-контейнера.
2. **Каждому `TTF_OpenFont` / `SDL_CreateTexture*` соответствует ровно один `TTF_CloseFont` / `SDL_DestroyTexture` на том же уровне владения.** Открыл сам — передай в `set_owned_font` немедленно, без промежуточных состояний.
3. **Никогда не затирать владеющий указатель присваиванием.** Только через метод, который сначала освобождает старое.
4. **Освобождение идемпотентно**: после `Close`/`Destroy` — сразу `nullptr`; повторный `cleanup()` ничего не делает.
5. **Не кодировать владение косвенными флагами** («кто установил значение», «пришло ли из палитры») — они разъезжаются с реальностью. `passed_by_font_palette` остался в коде, но теперь отвечает только за то, *обновляться ли по палитре*, и не участвует в освобождении памяти.
6. Если ресурс временно «переезжает» (пресс-анимация), **владение передаётся явно** и возвращается в конце (см. 3.4).

### 3.4. Как исправлена пресс-анимация

* На старте нажатия кнопка запоминает базовый шрифт (`po_base_font`, `po_base_size`) и **был ли он собственным** (`po_base_font_owned`), после чего забирает опекунство: `owned_font = nullptr`. Теперь шрифты промежуточных шагов свободно закрывают друг друга через `set_owned_font`, не задевая базовый.
* На каждом шаге — **одно** открытие: `TTF_OpenFont` → `set_owned_font(new_font)` + прямое обновление `font_size` (кнопка — friend текстбокса). Никаких вторых открытий через `set_font_size`.
* На отпускании базовый шрифт возвращается с восстановлением владения (`set_owned_font`/`set_shared_font` — последний пресс-шрифт закрывается внутри), размер восстанавливается полем, повторного `TTF_OpenFont` нет.
* Если кнопку уничтожили посреди нажатия — `My_SDL_button::cleanup()` сначала возвращает опекунство базового шрифта текстбоксу, затем зовёт `button_textbox.cleanup()`, так что и пресс-шрифт, и базовый освобождаются корректно.

### 3.5. Как исправлены палитровые пути кнопки

В `switch_button_textbox_type()` и `reset_button_textbox_if_font_palette_switched()` вызовы `set_font_size(палитровый размер)` (= лишний `TTF_OpenFont`) заменены прямым присваиванием поля `font_size`: палитровый шрифт уже открыт в нужном размере, открывать его копию незачем. Кнопки теперь реально сидят на общих шрифтах палитры — утечки из п. 1.5/1.6 исчезают вместе с самим дубликатом.

## 4. Мини-лекция: «как нормально выделяться», оставаясь на этой архитектуре

Архитектура «глобальные указатели стейта + `new` в enter + `delete_element()` в exit» — рабочая, менять её не нужно. Нужно лишь честно проходить полный жизненный цикл ресурса:

**Выделение → использование → освобождение — всегда в одном и том же владельце.**

1. **Стейт владеет элементами.** `new` только в `*_elements_create()`, `delete_element()` только в `*_elements_free_and_nullptr()`, после освобождения — `nullptr` (это уже сделано правильно). Глобальные указатели стейта на это не влияют — см. раздел 2.
2. **Элемент владеет своими SDL-объектами.** Всё, что элемент создал (`SDL_CreateTextureFromSurface`, `TTF_OpenFont`), он же и уничтожает в своём `cleanup()`. Всё, что элементу *дали* (палитровый шрифт, чужая текстура), он не трогает — только ссылается.
3. **Синглтоны владеют общими ресурсами до конца процесса.** Шрифты палитр закрывать по-хорошему нужно в общем shutdown-е, но их фиксированное число — это не утечка, а константа.
4. **Хочется строже — есть эволюционный путь без ломки:** приватный шрифт можно держать как

   ```cpp
   std::unique_ptr<TTF_Font, decltype(&TTF_CloseFont)> owned_font{nullptr, &TTF_CloseFont};
   ```

   — тогда «забыть закрыть» станет невозможно на уровне компилятора. Текущее исправление сознательно сделано на сырых указателях, чтобы остаться в стиле проекта; `unique_ptr` — опциональный следующий шаг.
5. **Проверка регрессий — циклом:** после любых правок в GUI-элементах прогонять «50 кликов / 20 переключений палитры / 20 переходов между стейтами» и смотреть на счётчики Open/Close (или снапшоты кучи). Рост на цикл = новая утечка.

Сводка правок:

* **my_sdl_button.h** — поле `po_base_font_owned`.
* **my_sdl_button.cpp** — конструктор: инициализация нового поля; `cleanup()`: возврат опекунства базового шрифта + делегирование `button_textbox.cleanup()`; `switch_button_textbox_type()` и `reset_button_textbox_if_font_palette_switched()`: `font_size` присваивается напрямую вместо повторного `TTF_OpenFont`, обновление и сброс `po_base_*` защищены от срабатывания во время нажатия; пресс-анимация: одно открытие на шаг с передачей владения, корректный возврат базового шрифта на release.

Публичный API классов не изменился — стейты и остальные элементы править не нужно (в `program_logic` `set_font_size`/`set_font_path` и так нигде не вызываются).

### Сценарий ручной проверки после внедрения

1. Собрать, открыть MAIN_MENU, записать Private Bytes (Process Explorer / диспетчер).
2. 50 раз кликнуть любую кнопку → цифра должна выйти на плато после первых кликов (раньше рос каждый клик).
3. 10 раз переключить шрифтовую палитру (🔤) и тему (🎨) → плато (раньше — рост на каждую смену шрифта).
4. 20 раз пройти цикл START ↔ MAIN_MENU → значение после каждого возврата в MAIN_MENU должно быть одинаковым (первый вход дороже — это кэш кучи, см. раздел 2).
