# Подход к программной обработке высокоскоростной видеосъемки (Approach)

Для автоматизированного извлечения физических параметров плазменного потока и дисперсной фазы (частиц порошка) применяется конвейер пошаговой обработки (pipeline) на базе библиотеки компьютерного зрения **OpenCV**. 

Поскольку плазменная струя (непрерывная фаза) и летящие частицы (дискретная фаза) обладают принципиально разными геометрическими и яркостными характеристиками, алгоритм разделяется на два независимых потока фильтрации с формированием параллельных бинарных масок.

---

## 1. Конвейер формирования масок (Image Segmentation Pipeline)

### А. Маска плазменной струи (Macro-level Mask)
Цель — выделить геометрию основного тела плазмы, отсекая летящие вокруг искры.
1. **Размытие по Гауссу (`cv::GaussianBlur`):** Применяется ядро большого размера (например, 15х15 или 21х21). Это «растворяет» отдельные мелкие треки частиц, превращая струю в монолитный градиент яркости.
2. **Пороговая бинаризация (`cv::threshold`):** Отсечение по фиксированному уровню серого цвета для выделения устойчивых границ факела.

### Б. Маска металлических частиц (Micro-level Mask)
Цель — полностью стереть фоновое свечение плазмы и оставить только контуры частиц.
1. **Вычитание фона (Background Subtraction):** Применяется покадровое вычитание соседних кадров (`cv::absdiff(Frame_N, Frame_N-1)`) либо скользящее среднее. Поскольку плазменная струя квазистационарна, а частицы движутся с экстремальной скоростью, данный шаг мгновенно стирает тело струи.
2. **Детектор Кэнни (`cv::Canny`):** Выделение резких границ и треков частиц.
3. **Морфологическое расширение (`cv::dilate`):** «Залечивание» микроразрывов в треках частиц для обеспечения замкнутости их контуров.

## 2. Математическое обоснование и алгоритмы расчета метрик

### 2.1. Средняя интенсивность излучения в кадре
* **Физический смысл:** Косвенная оценка мощности и радиационного теплообмена потока по отношению к эталонному источнику излучения.
* **Реализация в OpenCV:** Определение средней яркости пикселей в зоне интереса (ROI).
* **Формула расчета:** 
  $$\bar{I} = \text{cv::mean}(Image, M_{jet})$$
  Где $M_{jet}$ — маска исследуемой зоны. Для калибровки рассчитывается аналогичное значение $\bar{I}_{ref}$ для референсного светильника с известными энергетическими характеристиками.
* **Ограничение:** Присутствие пикселей с максимальным значением (255 для 8-бит или 65535 для 16-бит) свидетельствует о насыщении матрицы (saturation). В этих зонах расчет энергии нелинеен и требует превентивного снижения экспозиции камеры или установки нейтральных (ND) светофильтров.

### 2.2. Средняя амплитуда плазменной струи в начальной, переходной и основной зонах
* **Физический смысл:** Оценка пространственной устойчивости, расширения и пульсаций плазменного потока вдоль оси его распространения.
* **Реализация в OpenCV:**
  1. Маска струи (п. 1.А) разделяется по горизонтальной оси $X$ на три вертикальных подмассива (ROI), соответствующих геометрии сопла и дистанции напыления.
  2. В каждом ROI для каждой координаты $X_i$ вычисляется разность между максимальной и минимальной координатой $Y$ белых пикселей (верхняя и нижняя границы струи).
  3. Полученные значения ширины $W(X_i)$ усредняются по формуле:
     $$\bar{W}_{zone} = \frac{1}{N} \sum_{i=1}^{N} (Y_{max, i} - Y_{min, i}) \times \text{Pixel\_Scale}$$
* **Оптимизация:** Во избежание ложного срабатывания на границах из-за флуктуаций газа, граница определяется не жестким порогом, а по анализу профиля яркости — точкой, где интенсивность падает до 10% от осевого максимума.

### 2.3. Основное направление движения частиц (угол $\alpha_{main}$)
* **Физический смысл:** Определение вектора геометрической оси сопла и макроскопического направления плазменного потока.
* **Реализация в OpenCV:**
  1. На маске частиц (п. 1.Б) выделяются индивидуальные треки с помощью `cv::findContours`.
  2. Каждый контур аппроксимируется вектором направления с помощью `cv::fitLine` или метода главных компонент (`cv::PCA`). На выходе получается угол каждого трека $\alpha_j$.
  3. Строится статистическая гистограмма распределения углов всех частиц на выборке из 100+ кадров. Математическое ожидание (пик гистограммы) принимается за базовый вектор сопла $\alpha_{main}$.

### 2.4. Метрики отклонения частиц от основного направления
* **Метрики:** Процент частиц с отклонением $> 5^\circ$, средний угол отклонения, максимальный угол отклонения.
* **Физический смысл:** Интегральная оценка уровня турбулизации потока и интенсивности радиального рассеяния порошка.
* **Реализация в OpenCV:**
  Для каждого обнаруженного вектора частицы $\vec{V}_j$ вычисляется модуль угла отклонения относительно основного направления:
  $$\Delta \alpha_j = |\alpha_j - \alpha_{main}|$$
  * **Процент отклонения:** Расчет отношения количества частиц, где $\Delta \alpha_j > 5^\circ$, к общему числу векторов $N_{total}$ на кадре.
  * **Средний угол:** Математическое усреднение значений $\Delta \alpha_j$ для частиц, преодолевших порог в $5^\circ$.
  * **Максимальный угол:** Фиксация экстремума `cv::minMaxLoc` по всему массиву углов, исключая единичные шумы (отсекаются по минимальной площади контура).
* **Специфика:** Для исключения ошибок при пересечении треков частиц в плотном потоке, маска предварительно обрабатывается алгоритмом скелетизации (`cv::ximgproc::thinning`) для утончения линий до 1 пикселя.

### 2.5. Скорость движения частиц (в основном направлении и с отклонением)
* **Физический смысл:** Анализ кинематических свойств потока, ускорения частиц и эффективности передачи импульса от газа к материалу.
* **Реализация в OpenCV:**
  Зависит от режима работы высокоскоростной камеры:
  * **Режим «размытия» (Длинная экспозиция):** Скорость вычисляется по длине штриха (трека) $L_{pix}$ на одном кадре:
    $$V_j = \frac{L_{pix} \times \text{Pixel\_Scale (мм/пикс)}}{\text{Exposure\_Time (сек)}}$$
  * **Режим «точек» (Короткая экспозиция):** Применяется алгоритм оптического потока Лукаса-Канаде (`cv::calcOpticalFlowPyrLK`). Скорость вычисляется по смещению центра масс частицы $\Delta S$ между кадром $N$ и $N+1$:
    $$V_j = \Delta S \times \text{Pixel\_Scale} \times \text{Camera\_FPS}$$
  Разделение на «основную» и «отклоненную» скорость происходит на основе фильтрации массива скоростей по угловому критерию $\Delta \alpha_j \le 5^\circ$ и $\Delta \alpha_j > 5^\circ$ соответственно.

### 2.6. Число Рейнольдса ($Re$)
* **Физический смысл:** Фундаментальный критерий перехода потока от ламинарного к турбулентному режиму.
* **Реализация:** Напрямую средствами компьютерного зрения параметр не вычисляется, так как требует знания физико-химических констант среды. Данные из OpenCV используются в качестве прецизионных динамических входных параметров для классического уравнения гидродинамики:
  $$Re = \frac{\rho \cdot \bar{V} \cdot \bar{W}}{\mu}$$
  Где:
  * $\bar{V}$ — средняя скорость потока (получена из п. 2.5);
  * $\bar{W}$ — характерный диаметр струи в переходной зоне (получен из п. 2.2);
  * $\rho$ (плотность плазмы) и $\mu$ (динамическая вязкость) — табличные параметры, вычисляемые программно на основе средней интенсивности излучения $\bar{I}$ (п. 2.1), коррелирующей с температурой плазменного газа.

## 3. Необходимая калибровка системы
Для перевода абстрактных метрик компьютерного зрения (пиксели, углы на матрице) в физические величины (метры в секунду, миллиметры, градусы) перед обработкой видеопотока в конвейер закладывается матрица калибровки камеры (`cv::calibrateCamera`). Съемка калибровочной шахматной доски в плоскости плазменного сопла позволяет:
1. Компенсировать радиальную и тангенциальную дисторсию объектива высокоскоростной камеры.
2. Рассчитать точную цену пикселя (`Pixel_Scale`) в мм/пикс с учетом оптического увеличения и перспективных искажений.



## 4. Программный алгоритм покадрового анализа и калибровки рабочей зоны

Поиск и вычисление физических характеристик реализуются посредством последовательного пятиэтапного алгоритма с элементами интерактивной калибровки (Human-in-the-loop):

1. **Предварительная обработка и фильтрация спектра:**
   Для обеспечения физической достоверности данных исключаются алгоритмы генеративного (нейросетевого) изменения разрешения. Видеопоток переводится в формат анализа интенсивности. При использовании цветной матрицы изображение декомпозируется на каналы, либо переводится в пространство HSV, где канал **V (Value)** используется как прямой показатель яркости, изолированный от цветовых флуктуаций.

2. **Интерактивное пространственное зонирование:**
   Поскольку границы зон плазменной струи динамически изменяются в зависимости от частоты модуляции, применяется ручная сегментация кадра. Посредством графических трекбаров (интерфейс OpenCV HighGUI) оператор задает координаты вертикальных отсекающих плоскостей по оси $X$. Кадр разделяется на четыре изолированных региона интереса (ROI):
   * Зона среза сопла плазмотрона;
   * Начальный участок струи;
   * Переходный участок;
   * Основной участок.

3. **Мультимасочная фильтрация по регионам (Multi-mask Pipeline):**
   Для каждого выделенного ROI настраивается индивидуальный программный фильтр со своими параметрами, управляемыми через систему трекбаров в реальном времени:
   * **Маска сопла:** Выделяется в зоне сопла с помощью жесткого порога яркости для фиксации металлических границ.
   * **Маска струи:** Формируется во всех зонах, кроме сопла. Настраивается комбинацией `cv::GaussianBlur` (для сглаживания пульсаций) и `cv::inRange` (по яркостному критерию).
   * **Маска треков частиц:** Формируется на основе дифференциального вычитания кадров, фильтра `cv::Canny` и морфологической дилатации `cv::dilate` для получения замкнутых контуров летящих дисперсных объектов.

4. **Определение координатной системы и оптического масштаба (Геометрическая калибровка):**
   На основе маски сопла алгоритм локализует две крайние координатные точки его правой грани. По ним вычисляется уравнение прямой, описывающей плоскость среза. Вектор нормали к этой плоскости, проходящий через геометрический центр отрезка, принимается за **математическую ось сопла (базовый вектор направления движения потока $\vec{V}_{main}$)**. 
   Зная физический диаметр сопла $D_{real}$ (мм) и его программную длину в пикселях $D_{pix}$, вычисляется пространственный масштаб системы:
   $$\text{Pixel\_Scale} = \frac{D_{real}}{D_{pix}} \text{ [мм/пиксель]}$$

5. **Вычисление интенсивности излучения:**
   Расчет средней интенсивности светового потока $\bar{I}$ производится путем сканирования матрицы яркости кадра исключительно внутри динамической маски струи, исключая область сопла, что позволяет сопоставить мощность излучения при различных режимах модуляции с референсным источником.

6. **Расчет пространственной амплитуды струи:**
   На основе сформированных масок макро-уровня для трех технологических зон (начальной, переходной, основной) производится сканирование высоты профиля по оси $Y$. Средняя амплитуда (ширина) струи $\bar{W}_{zone}$ вычисляется как среднее арифметическое вертикальных сечений в пределах границ каждого ROI, скорректированное на пространственный масштаб `Pixel_Scale`.

7. **Экстракция векторов треков частиц (Точки А и B):**
   Для каждого дискретного контура на маске частиц вычисляется минимальный ориентированный прямоугольник (`cv::minAreaRect`). За начальную (A) и конечную (B) точки трека принимаются центры его противоположных торцевых граней. 
   * **Скорость частицы ($v$):** Вычисляется на основе евклидова расстояния между точками А и B:
     $$v = \frac{\sqrt{(X_B - X_A)^2 + (Y_B - Y_A)^2} \times \text{Pixel\_Scale}}{\text{Exposure\_Time}}$$
   * **Угол движения ($\alpha$):** Определяется как угол между прямой $(AB)$ и математической осью сопла (базовым вектором направления).

8. **Статистическая фильтрация флуктуаций и углов отклонения:**
   * **Основной угол потока ($\beta$):** Покадрово вычисляется среднее арифметическое углов $\alpha$ всех обнаруженных частиц. Итоговое значение усредняется по всему массиву кадров видеозаписи.
   * **Критерий значительного отклонения ($\gamma$):** Для исключения тригонометрической избыточности вводится модуль разности углов $\Delta\alpha = |\alpha - \beta|$. Все частицы, удовлетворяющие условию $\Delta\alpha > 5^\circ$, классифицируются как «отклоненные» (турбулентные). Их углы усредняются покадрово, а затем трансформируются в среднегеометрический угол неустойчивости струи $\gamma$.

9. **Сепарация скоростных потоков и расчет турбулизации:**
   Массив вычисленных скоростей покадрово разделяется на два независимых кластера по угловому признаку $\Delta\alpha$:
   * $\bar{v}_{main}$ — средняя скорость частиц, движущихся в основном ядре потока ($\Delta\alpha \le 5^\circ$);
   * $\bar{v}_{dev}$ — средняя скорость частиц с выраженным отклонением ($\Delta\alpha > 5^\circ$).
   
   Интегральная степень турбулизации потока (процент частиц с выраженным отклонением) определяется как:
   $$P_{dev} = \frac{N(\Delta\alpha > 5^\circ)}{N_{total}} \times 100\%$$
   Данный параметр рассчитывается для каждого кадра и усредняется по длине выборки, отражая глобальную стабильность модуляции.

10. **Расчет критерия Рейнольдса ($Re$):**
   Для верификации перехода режимов течения плазмы вычисляется число Рейнольдса. С целью минимизации погрешностей прямого измерения плотности среды, классическое уравнение трансформируется под известную физическую величину — массовый расход плазмообразующего газа $G$ (кг/с):
   $$Re = \frac{4 \cdot G}{\pi \cdot \bar{W}_{trans} \cdot \mu(\bar{I})}$$
   Где:
   * $\bar{W}_{trans}$ — средняя амплитуда струи в переходной зоне, полученная на шаге 1;
   * $\mu(\bar{I})$ — динамическая вязкость плазмы, определяемая по температурной функции, аппроксимированной на основе средней интенсивности излучения кадра $\bar{I}$.


## 5. SWOT


лавные плюсы архитектуры

Интерактивность вместо «слепой» автоматики: Идея вынести настройку масок (inRange, GaussianBlur, Canny, dilate) на ползунки (трекбары) — это главное спасение для научной работы. Физика плазмы слишком нестабильна. Написав «жесткий» автовыбор параметров, вы бы увязли в багах. Ручная калибровка зон и масок позволит вам за 5 минут настроить программу под любой новый видеофайл.

Экстремальная производительность: Использование C++ и OpenCV гарантирует, что покадровый анализ будет лететь. Отрисовка промежуточных масок через SDL_Texture (с которой мы начинали диалог) не будет тормозить процессор, так как SDL2 использует аппаратное ускорение видеокарты (GPU).

Физическая автономность расчетов: Переход на расчет числа Рейнольдса через массовый расход газа (\(G\)) и эквивалентный диаметр из OpenCV — это сильный математический ход. Вы убрали необходимость внедрять в программу сложные газодинамические симуляторы.


Один скрытый риск: 

Проблема «наложения» (Occlusion)

Единственное слабое место классического 2D компьютерного зрения в вашей задаче — это плотность потока частиц.

В чем риск: Камера видит мир плоским. Если одна летящая частица на траектории перекроет другую (одна окажется строго за другой), OpenCV увидит их как один большой трек. Если две частицы полетят наперерез, их треки образуют крест X, и алгоритм cv::findContours воспримет их как одну странную геометрическую фигуру. Из-за этого точки А и B определятся неверно, а скорость и угол «сломаются».

Как это лечится: В вашем алгоритме уже заложен предохранитель — статистика. Поскольку вы усредняете данные по сотням частиц и кадров (вычисление математического ожидания \(\beta \)), единичные ошибки слияния треков просто «растворятся» в общей массе и не повлияют на итоговый график турбулизации.


## 6. Пример

Для экономии места и читаемости тривиальные вещи (вроде полной инициализации окон) опущены, но ключевая математика и конвейер OpenCV расписаны полностью.


``` cpp

#include <opencv2/opencv.hpp>
#include <iostream>
#include <vector>
#include <cmath>

// Структура для хранения физических параметров одной частицы
struct ParticleTrack {
    cv::Point2f ptA;      // Начало трека
    cv::Point2f ptB;      // Конец трека
    double velocity;      // Скорость (м/с)
    double angleAlpha;    // Угол отклонения от оси сопла (градусы)
};

// --- ГЛОБАЛЬНЫЕ ПЕРЕМЕННЫЕ ДЛЯ НАСТРОЕКИ (ТРЕКБАРЫ) ---
int roi_nozzle_x = 100;   // Координата X окончания зоны сопла
int roi_trans_x = 300;    // Координата X окончания переходной зоны
int roi_main_x = 500;     // Координата X окончания основной зоны

int blur_size = 5;        // Размытие для струи
int thresh_jet = 120;     // Порог бинаризации струи

int canny_low = 30;       // Порог Canny для частиц
int dilate_iter = 1;      // Итерации дилатации для частиц

// Физические константы эксперимента (задаются исследователем)
const double EXPOSURE_TIME = 0.00002; // Экспозиция камеры, сек (например, 20 мкс)
const double NOZZLE_DIAMETER_MM = 8.0; // Физический диаметр сопла в мм
const double MASS_FLOW_RATE = 0.002;  // Массовый расход газа G, кг/с

// --- ВСПОМОГАТЕЛЬНЫЕ МАТЕМАТИЧЕСКИЕ ФУНКЦИИ ---

// Расчет угла между двумя векторами (в градусах)
double calculateAngle(cv::Point2f vec1, cv::Point2f vec2) {
    double dot = vec1.x * vec2.x + vec1.y * vec2.y;
    double det = vec1.x * vec2.y - vec1.y * vec2.x;
    double angle = std::atan2(det, dot) * 180.0 / CV_PI;
    return std::abs(angle); // Нам нужен модуль отклонения
}

// Заглушка для расчета динамической вязкости от интенсивности излучения
double getViscosity(double mean_intensity) {
    // В реальности здесь будет ваша аппроксимационная формула температуры
    // Например, линейная или полиномиальная зависимость mu(T(I))
    return 1.8e-5 + (mean_intensity * 1.5e-7); 
}

// Пустая функция для callback-трекбаров
void on_trackbar(int, void*) {}

int main() {
    // 1. Открытие видеофайла высокоскоростной съемки
    cv::VideoCapture cap("resources/video/plasma_highspeed.mp4");
    if (!cap.isOpened()) {
        std::cerr << "Ошибка открытия видео!" << std::endl;
        return -1;
    }

    // 2. Создание интерфейса управления калибровкой
    cv::namedWindow("Settings", cv::WINDOW_AUTOSIZE);
    cv::createTrackbar("ROI Nozzle X", "Settings", &roi_nozzle_x, 800, on_trackbar);
    cv::createTrackbar("ROI Trans X", "Settings", &roi_trans_x, 800, on_trackbar);
    cv::createTrackbar("Jet Threshold", "Settings", &thresh_jet, 255, on_trackbar);
    cv::createTrackbar("Canny Low", "Settings", &canny_low, 255, on_trackbar);

    cv::Mat frame, gray_frame, prev_gray;
    double pixel_scale = 1.0; // Будет вычислено по соплу (мм/пиксель)
    cv::Point2f nozzle_axis_vec(1.0f, 0.0f); // Базовый вектор оси (перпендикуляр к срезу)

    while (cap.read(frame)) {
        // Конвертируем в Grayscale (если видео цветное) или извлекаем канал V из HSV
        if (frame.channels() == 3) {
            cv::cvtColor(frame, gray_frame, cv::COLOR_BGR2GRAY);
        } else {
            gray_frame = frame.clone();
        }

        if (prev_gray.empty()) prev_gray = gray_frame.clone();

        int width = gray_frame.cols;
        int height = gray_frame.rows;

        // ==========================================
        // ЭТАП 1: ГЕОМЕТРИЧЕСКАЯ КАЛИБРОВКА (ЗОНА СОПЛА)
        // ==========================================
        cv::Mat nozzle_roi = gray_frame(cv::Rect(0, 0, roi_nozzle_x, height));
        cv::Mat nozzle_mask;
        cv::threshold(nozzle_roi, nozzle_mask, thresh_jet, 255, cv::THRESH_BINARY);

        // Поиск контура среза сопла для определения масштаба
        std::vector<std::vector<cv::Point>> nozzle_contours;
        cv::findContours(nozzle_mask, nozzle_contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
        
        if (!nozzle_contours.empty()) {
            // Ищем самый большой контур (само сопло)
            auto largest = std::max_element(nozzle_contours.begin(), nozzle_contours.end(), 
                [](const auto& c1, const auto& c2) { return cv::contourArea(c1) < cv::contourArea(c2); });
            
            cv::Rect nozzle_box = cv::boundingRect(*largest);
            double nozzle_diameter_pixels = nozzle_box.height; // Диаметр в пикселях по вертикали
            
            // Вычисляем масштаб: мм в одном пикселе
            pixel_scale = NOZZLE_DIAMETER_MM / nozzle_diameter_pixels;
        }

        // ==========================================
        // ЭТАП 2: ФОРМИРОВАНИЕ МАСКИ СТРУИ И МЕТРИКИ ЯРКОСТИ
        // ==========================================
        // Исключаем зону сопла из анализа струи
        cv::Mat jet_working_zone = gray_frame(cv::Rect(roi_nozzle_x, 0, width - roi_nozzle_x, height));
        
        // Расчет средней интенсивности излучения струи
        cv::Scalar mean_intensity_scalar = cv::mean(jet_working_zone);
        double mean_intensity = mean_intensity_scalar[0];

        // Маска струи (Размытие + Порог)
        cv::Mat jet_blur, jet_mask;
        int k_size = (blur_size % 2 == 0) ? blur_size + 1 : blur_size; // Гаусс требует нечетное ядро
        cv::GaussianBlur(jet_working_zone, jet_blur, cv::Size(k_size, k_size), 0);
        cv::threshold(jet_blur, jet_mask, thresh_jet, 255, cv::THRESH_BINARY);

        // Расчет средней амплитуды струи в переходной зоне (как пример)
        int trans_zone_start_x = roi_nozzle_x;
        int trans_zone_end_x = roi_trans_x;
        double sum_amplitude = 0;
        int active_columns = 0;

        for (int x = trans_zone_start_x; x < trans_zone_end_x && x < width; ++x) {
            // Сканируем вертикальный столбец маски струи
            cv::Mat col = jet_mask.col(x - roi_nozzle_x);
            int white_pixels = cv::countNonZero(col);
            if (white_pixels > 0) {
                sum_amplitude += white_pixels;
                active_columns++;
            }
        }
        double mean_amplitude_trans_pixels = (active_columns > 0) ? (sum_amplitude / active_columns) : 0;
        double mean_amplitude_trans_mm = mean_amplitude_trans_pixels * pixel_scale;

        // ==========================================
        // ЭТАП 3: АНАЛИЗ ЧАСТИЦ (ДИФФЕРЕНЦИАЛЬНАЯ МАСКА)
        // ==========================================
        cv::Mat frame_diff, particle_mask;
        cv::absdiff(gray_frame, prev_gray, frame_diff); // Вычитание фона
        
        cv::Canny(frame_diff, particle_mask, canny_low, canny_low * 3);
        cv::dilate(particle_mask, particle_mask, cv::Mat(), cv::Point(-1,-1), dilate_iter);

        // Поиск контуров индивидуальных треков частиц
        std::vector<std::vector<cv::Point>> particle_contours;
        cv::findContours(particle_mask, particle_contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

        std::vector<ParticleTrack> frame_tracks;
        double sum_alpha = 0;

        for (const auto& contour : particle_contours) {
            if (cv::contourArea(contour) < 15) continue; // Отсекаем мелкий шум

            // Вписываем ориентированный прямоугольник для поиска точек А и B
            cv::RotatedRect rect = cv::minAreaRect(contour);
            cv::Point2f vertices[4];
            rect.points(vertices);

            // Находим длинную ось прямоугольника (вектор трека)
            cv::Point2f ptA, ptB;
            double edge1 = cv::norm(vertices[0] - vertices[1]);
            double edge2 = cv::norm(vertices[1] - vertices[2]);
            
            if (edge1 > edge2) {
                ptA = (vertices[0] + vertices[3]) * 0.5f;
                ptB = (vertices[1] + vertices[2]) * 0.5f;
            } else {
                ptA = (vertices[0] + vertices[1]) * 0.5f;
                ptB = (vertices[2] + vertices[3]) * 0.5f;
            }

            // Физическая длина трека и расчет скорости
            double track_length_pixels = cv::norm(ptB - ptA);
            double velocity = (track_length_pixels * pixel_scale * 0.001) / EXPOSURE_TIME; // м/с

            // Расчет угла отклонения альфа относительно вектора сопла
            cv::Point2f track_vec = ptB - ptA;
            double alpha = calculateAngle(track_vec, nozzle_axis_vec);

            // Корректируем геометрию направления (угол должен быть острым, < 90)
            if (alpha > 90.0) alpha = 180.0 - alpha;

            frame_tracks.push_back({ptA, ptB, velocity, alpha});
            sum_alpha += alpha;
        }

        // ==========================================
        // ЭТАП 4: СТАТИСТИЧЕСКАЯ ПОСТ-ОБРАБОТКА КАДРА
        // ==========================================
        double beta = (frame_tracks.empty()) ? 0.0 : (sum_alpha / frame_tracks.size()); // Основной угол

        int turbulent_particles_count = 0;
        double sum_turbulent_velocity = 0;
        double sum_main_velocity = 0;
        int main_particles_count = 0;

        for (const auto& track : frame_tracks) {
            double delta_alpha = std::abs(track.angleAlpha - beta);

            if (delta_alpha > 5.0) { // Критерий значительного отклонения
                turbulent_particles_count++;
                sum_turbulent_velocity += track.velocity;
            } else {
                main_particles_count++;
                sum_main_velocity += track.velocity;
            }
        }

        // Итоговые покадровые метрики
        double percent_turbulent = (frame_tracks.empty()) ? 0.0 : ((double)turbulent_particles_count / frame_tracks.size() * 100.0);
        double avg_main_velocity = (main_particles_count > 0) ? (sum_main_velocity / main_particles_count) : 0.0;

        // Расчет числа Рейнольдса для кадра
        double dynamic_viscosity = getViscosity(mean_intensity);
        double characteristic_size_m = mean_amplitude_trans_mm * 0.001; // Переводим в метры
        
        // Re = (4 * G) / (pi * D * mu)
        double Reynolds = (4.0 * MASS_FLOW_RATE) / (CV_PI * characteristic_size_m * dynamic_viscosity);

        // =================================================================
        // ЭТАП 5: ВИЗУАЛИЗАЦИЯ И ИНТЕРАКТИВНЫЙ ВЫВОД НА ЭКРАН
        // =================================================================
        
        // 1. Отрисовка вертикальных линий зонирования поверх исходного кадра
        // Красная линия — граница среза сопла плазмотрона
        cv::line(frame, cv::Point(roi_nozzle_x, 0), cv::Point(roi_nozzle_x, height), cv::Scalar(0, 0, 255), 2);
        // Желтая линия — граница переходной зоны струи
        cv::line(frame, cv::Point(roi_trans_x, 0), cv::Point(roi_trans_x, height), cv::Scalar(0, 255, 255), 2);

        // 2. Формирование текстовой строки с рассчитанными физическими параметрами
        std::string info = "Re: " + std::to_string((int)Reynolds) + " | Turb: " + std::to_string(percent_turbulent) + "%";
        
        // Вывод текста телеметрии в левый верхний угол кадра
        cv::putText(frame, info, cv::Point(20, 40), cv::FONT_HERSHEY_SIMPLEX, 0.7, cv::Scalar(0, 255, 0), 2);

        // 3. Отображение окон с результатами обработки
        cv::imshow("Analysis Window", frame);          // Исходный кадр с разметкой и метриками
        cv::imshow("Particle Mask", particle_mask);    // Бинарная маска выделенных треков частиц

        // 4. Сохранение текущего кадра для дифференциального вычитания фона на следующем шаге
        prev_gray = gray_frame.clone(); 

        // 5. Обработка интерактивного цикла (задержка 1 мс для обновления трекбаров)
        // Если нажата клавиша ESC (код 27) — принудительно прерываем цикл анализа
        if (cv::waitKey(1) == 27) break;
    } // Конец основного цикла покадровой обработки видео (while)

    // Освобождение ресурсов и дескрипторов видеофайла
    cap.release();
    cv::destroyAllWindows();
    
    return 0;
}
```



### Разбор ключевых инженерных решений в этом коде:

1. **`cv::absdiff` (Вычитание фона):** Переменная `prev_gray` хранит предыдущий кадр. Операция `cv::absdiff(gray_frame, prev_gray, frame_diff)` оставляет на маске только то, что сдвинулось между кадрами с огромной скоростью (частицы), полностью стирая неподвижные детали.
2. **`cv::minAreaRect` для треков:** Контур частицы превращается в ориентированную "коробочку" (`RotatedRect`). Код автоматически определяет, какая сторона прямоугольника длиннее, и вычисляет координаты точек **А** и **B** ровно посередине торцов. Это решает проблему "мохнатых краев" контура.
3. **Безопасный `std::atan2`:** Функция расчета угла `calculateAngle` использует векторное и скалярное произведения. Это самый быстрый и безопасный способ в геометрии узнать угол между прямыми, который никогда не выдаст деление на ноль, даже если трек частицы станет строго вертикальным или горизонтальным.
4. **Покадровый расчет параметров:** Все статистические данные (`beta`, `percent_turbulent`, `Reynolds`) вычисляются внутри цикла для каждого кадра отдельно. Чтобы получить итоговые данные для отчета, вам останется лишь складывать эти покадровые значения в буфер (например, `std::vector<double>`) и в конце программы усреднить их или записать в текстовый файл.
