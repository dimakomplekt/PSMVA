# Обнаружение и анализ частиц

Документ описывает фактический алгоритм третьей маски: выделение центров следов частиц, оценку типичного смещения и сопоставление точек соседних кадров. Реализация находится в [1.3_FLOW_PARAMETERS_CALCULATION.cpp](../1.3_FLOW_PARAMETERS_CALCULATION.cpp).

## 1. Выделение точек на кадре

Для каждого кадра обработка выполняется в следующем порядке:

1. Кадр BGR переводится в HSV. Диапазоны `H`, `S`, `V` задаются параметрами маски; `inRange` оставляет пиксели внутри диапазона.
2. При ненулевых размерах размытия к HSV-изображению применяется небольшой Gaussian blur. Если хотя бы один размер равен нулю, размытие отключено.
3. К бинарной цветовой маске применяется Canny, затем дилатация прямоугольным ядром. Дилатация утолщает и соединяет близкие фрагменты границ, чтобы след одной частицы с меньшей вероятностью распался на несколько контуров.
4. `findContours(RETR_EXTERNAL, CHAIN_APPROX_NONE)` извлекает внешние контуры.
5. Контур принимается, только если его площадь лежит в `[area_min, area_max]`, а длина — в `[length_min, length_max]`. Дополнительно отбрасываются плотные контуры (`solidity > 0.65`) и контуры с шириной или высотой ограничивающего прямоугольника больше 45 пикселей.
6. Координатой обнаружения становится центр ограничивающего прямоугольника: `x = rect.x + rect.width / 2`, `y = rect.y + rect.height / 2`. Эта точка добавляется в список детекций кадра.

Таким образом, центр здесь — **центр bounding box**, а не центроид контура, вычисленный через моменты. Контурные и геометрические фильтры предназначены для отбора вытянутых разреженных следов и отсева мелкого шума и крупных заполненных областей. Такой центр прост и дешёв в вычислении, но может смещаться относительно физического центра при изменении формы или ориентации следа; параметры маски следует подбирать и проверять на реальных кадрах.

## 2. Проход 1: калибровка типичного смещения

После сбора точек для видео оценивается опорное смещение между соседними кадрами. Оно задаёт ожидаемое перемещение для второго прохода.

Для каждой пары кадров `n`, `n+1`:

1. В кадре `n+1` рассматриваются **все точки** в правой зоне `zone_2_x_min_c * width < x < zone_2_x_max_c * width` (текущие границы — `0.85 * width` и `1.0 * width`).
2. Для каждой такой точки `q` кадра `n+1` в кадре `n` строится индивидуальный горизонтальный интервал поиска:

   ```text
   q.x - zone_1_x_max_c_delta * width < p.x
   p.x < q.x - zone_1_x_min_c_delta * width
   ```

   При текущих настройках это расстояние влево от `q.x` на `2–20%` ширины кадра.
3. Среди точек кадра `n`, попавших в этот X-интервал, выбирается точка `p` с минимальным `|q.y - p.y|`. Кандидат может быть как выше, так и ниже `q`; вертикальное расстояние должно быть не больше `pixel_spread` (сейчас 50 пикселей). Если подходящей точки нет, для `q` пара не добавляется.
4. Каждая найденная пара `(p, q)` сохраняется отдельно, и её `dx = q.x - p.x`, `dy = q.y - p.y` добавляются в выборку. Одна точка кадра `n` может быть выбрана для нескольких точек кадра `n+1` — уникальность сопоставления на этом калибровочном проходе не ограничивается.
5. По всем найденным парам отдельно вычисляются медиана и арифметическое среднее для `dx` и `dy`. Они смешиваются с весом `median_weight` (текущий вес медианы — `0.5`), после чего переводятся из пикселей в миллиметры через `mm_in_pixel`. Результат — `reference_dx` и `reference_dy`.

Правая зона выбрана как область калибровки для направленного потока. Использование всех точек в зоне даёт больше наблюдений, чем выбор только верхней и нижней крайних точек. Смешивание медианы и среднего сохраняет робастность медианы к выбросам, но учитывает вклад остальных наблюдений. Калибровка предполагает преимущественно правое движение и наличие подходящих следов в правой зоне; это прикладная оценка тренда, а не независимая физическая модель движения.

## 3. Проход 2: сопоставление соседних кадров

Для каждой пары точек `p` кадра `n` и `q` кадра `n+1` строится оценка соответствия. Опорные смещения переведены в миллиметры; фактические смещения рассчитываются с тем же масштабом `scale`:

```text
dx = (q.x - p.x) * scale
dy = abs(q.y - p.y) * scale
```

Пары с `dx <= 0` сразу получают оценку `0`: обратное или нулевое горизонтальное движение не допускается. Для остальных пар:

```text
error_x = abs(dx - reference_dx)
error_y = abs(dy - reference_dy)
score_x = exp(-error_x / (5 * scale))
score_y = exp(-error_y / (5 * scale))
score   = 0.5 * score_x + 0.5 * score_y
```

Иными словами, оценка лежит в диапазоне `[0, 1]`, идеальное совпадение с калибровочным смещением даёт `1`, а ошибка плавно уменьшает score. В текущей реализации координаты X и Y имеют одинаковый вес; знаменатель `5 * scale` задаёт экспоненциальный масштаб ошибки, эквивалентный пяти пикселям.

Затем применяется итеративное жадное сопоставление:

1. Для каждой ещё не сопоставленной точки кадра `n` выбирается её лучший доступный кандидат в кадре `n+1`.
2. Кандидат рассматривается, только если его `score >= 0.5`.
3. Если несколько точек кадра `n` претендуют на одну точку `n+1`, сохраняется претендент с более высоким score. При конфликте с не лучшим score код дополнительно использует направление вертикального смещения: если новый претендент движется вниз, а текущий победитель — нет, замена текущего победителя происходит с вероятностью 50%.
4. Зафиксированные пары удаляются из наборов доступных точек, после чего поиск повторяется для оставшихся. Цикл заканчивается, когда на очередной итерации не образуется ни одной пары.
5. Непарные точки остаются без соответствия в этой паре кадров: точки могут входить в кадр, выходить из него или не иметь достаточно убедительной пары.

Это **не Венгерский алгоритм**: хотя для всех комбинаций точек создаётся матрица оценок, алгоритм не ищет глобальный минимум суммарной стоимости. Он выбирает локально лучшие пары по итерациям и разрешает конфликты между претендентами. Поэтому результат не гарантирует глобально оптимальное назначение и может зависеть от порядка точек; случайный 50-процентный вертикальный tie-break делает отдельные конфликтные случаи недетерминированными.

### Почему выбран такой подход

- Опорное смещение из первого прохода использует ожидаемое движение потока, а не только расстояние между двумя точками. Это помогает отличать похожие по близости варианты, если их перемещения существенно расходятся с общим трендом.
- Порог `0.5` позволяет оставить часть детекций без пары вместо принудительного назначения сомнительных соответствий. Это важно при появлении/исчезновении частиц и при пропусках детектора.
- Взаимно-однозначная фиксация пар предотвращает использование одной детекции следующего кадра несколькими треками.
- Эвристика проще для настройки и объяснения в условиях направленного потока с известным типичным смещением. Венгерский алгоритм также возможен, но для него пришлось бы явно задать стоимости пропуска/появления частиц; при этом он решал бы другую задачу — глобальную оптимизацию назначения, а не выбор уверенных локальных пар.

Подход следует считать специализированной эвристикой, а не универсально более точным или быстрым методом. Матрица оценок всё равно требует сравнения каждой точки кадра `n` с каждой точкой кадра `n+1`; выигрыш в вычислительной производительности относительно альтернатив без измерений утверждать нельзя. Качество результата зависит от качества детекций, настроек маски и того, насколько стабильно смещение потока описывается одной опорной парой `reference_dx`, `reference_dy`.

## 4. Расчёт скорости, угла и характеристик потока

Каждое найденное соответствие между соседними кадрами образует отдельный отрезок движения:

```text
dx_mm = (x(n+1) - x(n)) * scale
dy_mm = (y(n+1) - y(n)) * scale
length_mm = sqrt(dx_mm^2 + dy_mm^2)
speed_m_s = (length_mm / 1000) / frame_time
angle_deg = atan2(dy_mm, dx_mm) * 180 / pi
```

При неположительном `frame_time` скорость устанавливается в `0`. Угол вычисляется в системе координат изображения OpenCV, где `Y` растёт вниз, и нормализуется диапазоном `[-180, 180]`.

Сопоставления выполняются **отдельно для каждой пары соседних кадров**; устойчивые ID частиц и сквозные траектории на всём видео не строятся. Итоговые агрегаты рассчитываются по полученным отрезкам движения:

- Для скорости и угла вычисляются медиана и среднее, затем их смешивают с весом `median_weight` (по умолчанию `0.5`).
- `main_speed` — смешанная скорость всех найденных отрезков. `main_angle` — смешанный угол относительно оси сопла (`nozzle_axe_angle`).
- Отрезок классифицируется как отклонённый, если его угол отличается от смешанного общего угла более чем на `max(10°, abs(общий_угол) * deflection_percentage / 100)`. Сейчас `deflection_percentage` равен `5`.
- По прямым и отклонённым отрезкам отдельно рассчитываются смешанные скорости. `deviation_angle` — blend среднего и медианы модулей углов отклонённых отрезков от общего направления, а `deviation_percentage` — доля отклонённых среди всех найденных отрезков.
- Для каждого кадра находится максимальный модуль отклонения среди классифицированных отклонёнными треков; `max_deviation_angle` — blend среднего и медианы этих покадровых максимумов. Кадры без отклонённых треков в агрегат не входят.
- `max_deviation_angle_all_frames` — наибольший модуль отклонения среди всех классифицированных отклонёнными треков в видео; это абсолютный максимум, без blend’а.
- Для последовательных обработанных пар кадров рассчитываются абсолютные изменения смешанных скорости и угла; итоговые `frames_speed_delta` и `frames_angle_delta` также являются смесью медианы и среднего.

## 5. Ограничения текущей реализации

- Калибровка и жёсткий запрет `dx <= 0` предполагают движение слева направо. Для иного направления эти правила нужно менять.
- При сопоставлении `dy` берётся по модулю, но `reference_dy` калибруется со знаком. Поэтому текущая формула предполагает неотрицательное вертикальное опорное смещение; движение с отрицательным `reference_dy` будет получать заниженную оценку по Y.
- Конфликтный вертикальный tie-break использует `rand()`, поэтому результаты для таких конфликтов могут меняться между запусками.
- Угол агрегируется обычными средним и медианой, а не круговой статистикой. Если значения сосредоточены около границы `-180°/180°`, агрегат может быть некорректным.
- Порог `pixel_spread` задан в пикселях, тогда как остальные смещения для сопоставления переводятся в миллиметры. При изменении разрешения видео этот параметр требует отдельной проверки.
- Численные ограничения геометрии следов и HSV-диапазоны задаются параметрами маски; результаты необходимо проверять на размеченных кадрах целевого видео.
